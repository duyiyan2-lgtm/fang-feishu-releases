# 01 · 需求分析

## 🎯 阶段目标

通过用户调研、竞品分析、业务梳理，输出**完整、可追溯、可验证**的需求规格说明书（SRS），为后续设计、开发和测试提供基线。

## 📝 必含章节（每篇需求文档）

| 章节 | 说明 | 必含配图 |
| :--: | :-- | :--: |
| 一、需求背景 | 业务痛点、用户场景 | ✅ |
| 二、用户角色 | 角色清单与画像 | ✅ |
| 三、用户故事 | User Story + 验收标准（Given/When/Then） | ❌ |
| 四、业务流程 | 端到端流程（业务流程图） | ✅ |
| 五、功能需求 | FR 清单（功能 ID + 描述 + 优先级） | ❌ |
| 六、非功能需求 | 性能 / 安全 / 可用性 / 兼容性 | ❌ |
| 七、需求追溯矩阵 | RTM（需求 → 设计 → 代码 → 测试） | ✅ |
| 八、变更记录 | 需求变更与版本历史 | ❌ |

## 📂 命名规范

```
01-需求分析-<模块名>-<文档名>.md
```

示例：
- `01-需求分析-IM-消息已读未读.md`
- `01-需求分析-审批-自定义表单.md`

## 🖼 配图要求

- 每篇文档 **≥ 5 张配图**（业务流程图、状态机图、界面原型草图）
- 存放：`docs/01-需求分析/images/` 子目录
- 推荐工具：draw.io / ProcessOn / Visio

## 📦 产出物清单

- [ ] 需求规格说明书（SRS）
- [ ] 用户故事地图（User Story Map）
- [ ] 业务流程图（每模块 1 张）
- [ ] 需求追溯矩阵（RTM）
- [ ] 竞品分析报告（飞书 / 钉钉 / 企业微信 对比）

## ✍️ 文档模板（复制后填写）

```markdown
# <模块名> - <需求主题>

## 一、需求背景
（业务痛点、为什么要做、用户场景）

## 二、用户角色
| 角色 | 描述 | 关键诉求 |
| :--: | :-- | :-- |

## 三、用户故事
- 作为 <角色>，我希望 <目标>，以便 <价值>
  - 验收标准：
    - Given <前置>
    - When <动作>
    - Then <结果>

## 四、业务流程
（插入业务流程图）

## 五、功能需求
| FR-ID | 描述 | 优先级 | 验收标准 |
| :--: | :-- | :--: | :-- |

## 六、非功能需求
- 性能：QPS / 响应时间
- 安全：鉴权 / 加密 / 审计
- 可用性：SLA / 故障恢复
- 兼容性：浏览器 / 设备 / 系统

## 七、需求追溯矩阵
| FR-ID | 设计文档 | 代码入口 | 测试用例 |
| :--: | :-- | :-- | :-- |

## 八、变更记录
| 版本 | 日期 | 修改人 | 变更内容 |
```
