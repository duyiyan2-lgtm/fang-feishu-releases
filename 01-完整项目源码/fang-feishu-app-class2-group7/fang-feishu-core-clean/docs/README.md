## 二·、多端覆盖一览

> 仿飞书应用 **6 端同步交付**，前端代码统一出自 `frontend/` 下的 5 个子工程。

| 端 | 形态 | 输出目录 | 编译工具 |
| :--: | :--: | :--: | :--: |
| 💻 PC 网页端 | Web | `frontend/pc-web/` | Vite |
| 🖥️ PC 客户端 | Desktop | `frontend/pc-client/` | Electron / Tauri |
| 📱 移动 H5 | Web | `frontend/mobile-h5/` | Uni-app |
| 📲 微信小程序 | Mini Program | `frontend/mini-program/` | Uni-app 编译 → 微信开发者工具 |
| 🍎 iOS App | App | `frontend/mobile-app/` | Uni-app 编译 |
| 🤖 Android App | App | `frontend/mobile-app/` | Uni-app 编译 |

> 💡 **小程序特别说明**：微信小程序有自己的一套 API（`wx.*`），与 H5/App 不完全通用。Uni-app 抹平了大部分差异，但**部分原生能力**（如蓝牙、扫码）仍需用条件编译 `#ifdef MP-WEIXIN` 单独处理。

## 四、文档命名规范总则

### 4.1 通用规则

```
<阶段编号>-<阶段名>-<模块名>-<文档主题>.md
```

示例：
- `01-需求分析-IM-消息已读未读.md`
- `04-数据库设计-用户中心-用户表.md`
- `06-前端开发-IM-消息列表组件.md`

### 4.2 特殊命名

| 类型 | 命名 | 示例 |
| :-- | :-- | :-- |
| 阶段索引 | `<编号>-<阶段名>/README.md` | `01-需求分析/README.md` |
| 全局文档 | `<编号>-<阶段名>-<主题>.md` | `04-数据库设计-全局ER图.md` |
| 阶段总结 | `<编号>-<阶段名>-总结报告.md` | `08-联调测试-总结报告.md` |
| 日报 | `日报-YYYY-MM-DD.md` | `日报-2026-07-15.md` |
| 周报 | `周报-W{n}-YYYY.md` | `周报-W3-2026.md` |
| 复盘 | `复盘-<阶段名>.md` | `复盘-需求阶段.md` |

### 4.3 命名禁忌

- ❌ 不要用中文空格、特殊符号（`!@#$%^&*`）
- ❌ 不要用纯中文标题（如 `消息列表组件.md`）→ 应是 `06-前端开发-IM-消息列表组件.md`
- ❌ 不要把"日志/笔记"放进 `docs/`，应放到 `docs/11-周报与复盘/`

## 五、文档配图规范总则

### 5.1 配图硬性要求

- **每个过程**都必须有**完整、具体**的配图
- 截图必须**清晰**（1080P+），关键位置用**红框/箭头**标注
- 每篇文档**最少配图数**见上表第二列（5 ~ 8 张）

### 5.2 配图存放

```
docs/<阶段>/images/<文档同名>.png
```

示例：
- `docs/01-需求分析/images/01-需求分析-IM-消息已读未读-业务流程.png`
- `docs/06-前端开发/images/06-前端开发-IM-消息列表组件-运行截图.png`

### 5.3 配图类型与推荐工具

| 类型 | 用途 | 推荐工具 |
| :--: | :-- | :--: |
| 架构图 | 系统/模块整体架构 | draw.io / ProcessOn |
| 流程图 | 业务流程、状态机 | draw.io / Visio |
| 时序图 | 接口调用、消息流转 | draw.io / PlantUML |
| 类图 | 领域模型、UML | draw.io / StarUML |
| ER 图 | 数据库表关系 | DBeaver / Navicat / draw.io |
| 界面截图 | 高保真原型、运行效果 | Snipaste / FSCapture |
| 代码截图 | 关键逻辑 | VS Code / 微信截图 |
| 监控截图 | Grafana Dashboard | Grafana 自带 |
| 性能曲线 | JMeter / Locust 报告 | JMeter / Locust |

### 5.4 配图禁忌

- ❌ 不要用手机随手拍电脑屏幕（模糊不清）
- ❌ 不要把图片直接贴到飞书/语雀再导出（会失真）
- ❌ 不要省略对图片的说明文字（每张图下方要有一句话解释）

## 六、文档评审流程

### 6.1 评审触发

- 每个阶段结束时（建议 W2、W4、W6、W8、W10、W12、W14）
- 每个业务模块 PR 合并前
- 每次重大变更后

### 6.2 评审检查清单

每篇文档评审时，评审人必须对照以下清单：

- [ ] 文件名是否符合命名规范
- [ ] 是否包含本阶段 README 模板中的所有必含章节
- [ ] 配图是否齐全（达到最小配图数）
- [ ] 配图是否清晰、有标注
- [ ] 关键代码是否有注释
- [ ] 关联文档（需求 → 设计 → 代码 → 测试）是否在文末给出链接
- [ ] 变更记录是否更新

### 6.3 评审人

| 文档类型 | 一审 | 二审 |
| :-- | :--: | :--: |
