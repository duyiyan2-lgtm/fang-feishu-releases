# 08 · 联调测试

## 🎯 阶段目标

通过**功能测试、接口测试、UI 自动化、压力测试**多维度验证系统质量，输出可追溯的测试报告与 Bug 清单。

## 📝 必含章节（每篇测试文档）

| 章节 | 说明 | 必含配图 |
| :--: | :-- | :--: |
| 一、测试范围 | 本轮测试覆盖的模块 | ✅ |
| 二、测试策略 | 测试类型 + 工具 + 准入准出 | ✅ |
| 三、测试用例 | 编号 + 步骤 + 预期 + 实际 | ✅ |
| 四、缺陷清单 | Bug ID + 等级 + 状态 | ✅ |
| 五、性能测试 | QPS / 响应时间 / 资源占用 | ✅ |
| 六、回归测试 | 修复后回归范围与结果 | ✅ |
| 七、风险与遗留 | 已知问题 + 后续计划 | ❌ |

## 📂 命名规范

```
08-联调测试-<轮次>-<范围>.md
```

示例：
- `08-联调测试-第1轮-用户中心.md`
- `08-联调测试-性能测试-IM.md`

## 🖼 配图要求

- 测试用例执行截图
- Bug 截图（带红框）
- 性能曲线图（JMeter / Locust 报告）
- 覆盖率报告
- **每篇 ≥ 6 张配图**

## 📦 产出物清单

- [ ] 测试计划
- [ ] 测试用例库（TestLink / 飞书表格）
- [ ] 缺陷清单（Bug 跟踪表）
- [ ] 性能测试报告
- [ ] 测试报告（`08-联调测试-总结报告.md`）
- [ ] 自动化测试脚本（`backend/tests/`、`frontend/tests/`）
