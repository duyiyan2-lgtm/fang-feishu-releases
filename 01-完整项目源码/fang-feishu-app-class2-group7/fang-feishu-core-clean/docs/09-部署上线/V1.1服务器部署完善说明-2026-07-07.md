# V1.1 服务器部署完善说明

## 一、完善目标

本次完善基于 `fang-feishu-core-cleanV1.1`，目标是补齐 Debian 12 服务器部署能力。

完善前，项目已经具备 Windows 本地一键启动能力：

```powershell
.\backend\scripts\start-full.ps1
```

完善后，项目新增 Debian/Linux 服务器部署能力：

```bash
./backend/scripts/start-full.sh
```

## 二、新增文件

| 文件 | 作用 |
| --- | --- |
| `deploy/docker/.env.prod.example` | 生产环境变量模板，存放域名、数据库密码、MinIO 密码、JWT 密钥等配置 |
| `deploy/docker/docker-compose.prod.yml` | Debian 服务器生产部署 Compose 文件 |
| `deploy/nginx/fang-feishu-api.conf` | Nginx 反向代理配置，支持 API、Swagger、SignalR WebSocket |
| `backend/scripts/start-full.sh` | Linux 一键启动完整后端系统脚本 |
| `backend/scripts/stop-full.sh` | Linux 一键停止完整后端系统脚本 |
| `docs/09-部署上线/Debian12服务器部署说明.md` | Debian 12 部署操作文档 |
| `docs/09-部署上线/V1.1服务器部署完善说明-2026-07-07.md` | 本说明文件 |

## 三、生产 Compose 设计

生产 Compose 文件：

```text
deploy/docker/docker-compose.prod.yml
```

包含服务：

| 服务 | 说明 |
| --- | --- |
| `api` | ASP.NET Core 后端 API |
| `postgres` | PostgreSQL 16 数据库 |
| `minio` | MinIO 文件存储 |

## 四、安全调整

### 1. 数据库不暴露公网

生产 Compose 没有把 PostgreSQL 端口映射到公网。

API 通过 Docker 内部服务名连接数据库：

```text
postgres:5432
```

### 2. API 只绑定本机

API 端口绑定为：

```text
127.0.0.1:5080:8080
```

公网请求需要经过 Nginx 代理，不直接暴露 API 容器端口。

### 3. MinIO 只绑定本机

MinIO 端口绑定为：

```text
127.0.0.1:9000:9000
127.0.0.1:9001:9001
```

避免文件存储管理端口直接暴露到公网。

### 4. 密码全部移到 `.env.prod`

生产密码不写死在 Compose 文件中，而是从：

```text
deploy/docker/.env.prod
```

读取。

该文件不应提交到仓库。

## 五、Nginx 支持内容

Nginx 配置文件：

```text
deploy/nginx/fang-feishu-api.conf
```

支持代理：

| 路径 | 说明 |
| --- | --- |
| `/health` | 健康检查 |
| `/api/` | 后端 REST API |
| `/swagger` | Swagger 接口文档 |
| `/hubs/im` | SignalR 即时通讯 WebSocket |

其中 `/hubs/im` 已配置：

```nginx
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
```

可支持 IM 实时通信。

## 六、脚本行为

### 启动

```bash
./backend/scripts/start-full.sh
```

脚本会：

1. 检查 Docker Engine 是否运行。
2. 检查 `deploy/docker/.env.prod` 是否存在。
3. 若 `.env.prod` 不存在，自动从 `.env.prod.example` 复制一份并提示用户修改。
4. 执行 `docker compose up -d --build`。
5. 轮询 `/health`，确认 API 是否启动成功。

### 重置

```bash
./backend/scripts/start-full.sh --reset
```

脚本会先执行：

```bash
docker compose down -v
```

再重新构建并启动。

### 停止

```bash
./backend/scripts/stop-full.sh
```

### 停止并删除数据

```bash
./backend/scripts/stop-full.sh --remove-volumes
```
