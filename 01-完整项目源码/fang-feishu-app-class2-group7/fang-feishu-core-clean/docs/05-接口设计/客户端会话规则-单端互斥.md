# 客户端会话规则：单端互斥

## 规则

同一账号允许同时登录四种客户端，但每种客户端只允许保留一个有效会话：

| 客户端类型 | `clientType` | 再次登录的影响 |
| --- | --- | --- |
| Web 网站 | `Web` | 仅使旧 Web 会话失效 |
| PC 客户端 | `Desktop` | 仅使旧 PC 客户端会话失效 |
| 微信小程序 | `MiniProgram` | 仅使旧小程序会话失效 |
| Android App | `Android` | 仅使旧 Android 会话失效 |

因此，同一账号可以同时使用 Web、PC、小程序和 Android；但两台 Android 手机登录同一账号时，后登录的手机会使先登录的 Android 自动退出。

## 登录接口约定

`POST /api/v1/auth/login` 和 `POST /api/v1/auth/register` 的请求体新增可选字段 `clientType`。未传时后端按 `Web` 处理。

```json
{
  "username": "admin",
  "password": "123456",
  "clientType": "MiniProgram"
}
```

也可以使用请求头作为兼容方式：

```text
X-Client-Type: Desktop
```

请求体中的 `clientType` 优先级高于请求头。

## 前端处理要求

当接口返回 `401` 且错误原因为同类型客户端重新登录时：

1. 清除本地 token 和用户缓存。
2. 返回登录页。
3. 提示“该账号已在另一台同类型设备登录”。

Android 原生端已完成上述处理。Web、PC、小程序在各自的请求拦截器中按相同规则处理。

## 后端实现

后端使用 `user_client_sessions` 表按 `用户 ID + 客户端类型` 保存会话版本。每次同类型登录递增版本；JWT 携带客户端类型和会话版本，鉴权时不一致即返回 `401`。
