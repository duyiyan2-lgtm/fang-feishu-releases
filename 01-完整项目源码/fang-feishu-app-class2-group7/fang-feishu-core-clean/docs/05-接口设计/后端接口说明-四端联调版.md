## 2. 统一规则

### 2.1 统一返回格式

正常返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "traceId": "0HNM..."
}
```

创建成功时，`message` 通常是：

```json
{
  "code": 0,
  "message": "created",
  "data": {},
  "traceId": "0HNM..."
}
```

业务失败时：

```json
{
  "code": 1503,
  "message": "No conversation permission.",
  "data": null,
  "traceId": "0HNM..."
}
```

### 2.2 Token 鉴权规则

除登录接口和健康检查外，大部分接口都需要 Token。

请求头格式：

```text
Authorization: Bearer {token}
```

注意只写一个 `Bearer`，不要写成：

```text
Bearer Bearer {token}
```

登出接口 `POST /api/v1/auth/logout` 会撤销当前 Token。成功登出后，再用同一个 Token 请求受保护接口，预期返回 `401`。

### 2.3 常见 HTTP 状态码

| 状态码 | 含义 | 常见原因 |
| :-- | :-- | :-- |
| `200` | 请求成功 | 查询、更新、删除成功 |
| `201` | 创建成功 | 新建文档、发消息、上传文件、提交审批成功 |
| `400` | 参数错误 | JSON 格式错误、GUID 格式错误、必填参数缺失 |
| `401` | 未登录或 Token 无效 | 没带 Token、Token 写错、Token 过期 |
| `403` | 没有权限 | 普通用户访问管理员接口 |
| `404` | 数据不存在 | ID 不存在，或访问了不属于自己的日程 |
| `500` | 后端异常 | 需要后端成员 A/D 查看日志 |

### 2.4 GUID 参数说明

接口中带 `id`、`userId`、`departmentId`、`conversationId`、`fileId` 的地方，一般都需要 GUID。

正确示例：

```text
def2aa52-d353-4c7a-ad5d-d1279fb4d013
```

错误示例：

```text
a1
123456
test
```

## 3. 推荐联调顺序

前端和测试建议按下面顺序跑通，不要一开始就直接测复杂业务。

### 第一步：健康检查

```http
GET /health
```

预期：

```json
{
  "status": "Healthy"
}
```

### 第二步：登录拿 Token

```http
POST /api/v1/auth/login
```

请求体：

```json
{
  "username": "admin",
  "password": "123456"
}
```

返回重点：

```json
{
  "data": {
    "token": "eyJhbGciOi...",
    "user": {
      "username": "admin",
      "roles": ["Admin"]
    }
  }
}
```

### 第三步：带 Token 获取当前用户

```http
GET /api/v1/auth/me
Authorization: Bearer {token}
```

预期：返回当前登录用户信息。

### 第四步：测试退出登录

```http
POST /api/v1/auth/logout
Authorization: Bearer {token}
```

预期：返回当前被撤销的 `tokenId` 和 `expiresAt`。

### 第五步：测试通讯录

```http
GET /api/v1/contacts
Authorization: Bearer {token}
```

预期：返回 5 个初始化用户。

### 第六步：测试 IM

先获取会话：

```http
GET /api/v1/im/conversations
```

复制返回中的 `id`，作为 `conversationId`。

发送消息：

```http
POST /api/v1/im/messages
```

请求体：

```json
{
  "conversationId": "def2aa52-d353-4c7a-ad5d-d1279fb4d013",
  "content": "这是测试消息",
  "messageType": "Text",
  "fileId": null
}
```

查询历史消息：

```http
GET /api/v1/im/conversations/{conversationId}/messages?page=1&pageSize=30
```

### 第七步：测试文档、云盘、审批、日历

依次测试：

```text
文档：创建 -> 详情 -> 更新 -> 评论 -> 版本
云盘：上传 -> 列表 -> 下载 -> 删除
审批：提交 -> 管理员查看 -> 管理员通过/驳回 -> 申请人查看结果
日历：创建 -> 列表 -> 更新 -> 删除
```

## 6. 前端请求封装建议

### 6.1 Axios 示例

```javascript
import axios from 'axios'

const request = axios.create({
  baseURL: 'http://120.76.54.147',
  timeout: 10000
})

request.interceptors.request.use(config => {
  const token = localStorage.getItem('token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

export default request
```

### 6.2 uni.request 示例

```javascript
const baseUrl = 'http://120.76.54.147'

export function request(options) {
  const token = uni.getStorageSync('token')
  return new Promise((resolve, reject) => {
    uni.request({
      url: baseUrl + options.url,
      method: options.method || 'GET',
      data: options.data || {},
      header: {
        Authorization: token ? `Bearer ${token}` : '',
        ...(options.header || {})
      },
      success: res => {
        if (res.statusCode === 401) {
          uni.removeStorageSync('token')
        }
        resolve(res.data)
      },
      fail: reject
    })
  })
}
```

## 8. 常见问题

### 8.1 Swagger 提示 Unauthorized

检查是否点击右上角 `Authorize`，并填写：

```text
Bearer {token}
```

### 8.2 departmentId 报 Value must be a Guid

`departmentId` 不能随便填。可以先留空，或复制接口返回里的真实部门 ID。

### 8.3 手机端/小程序请求失败

重点检查：

```text
1. 是否还在使用 localhost
2. 后端是否监听局域网地址
3. Windows 防火墙是否放行 5000 端口
4. 微信小程序正式环境是否配置 HTTPS 合法域名
5. 请求头是否带 Authorization
```

### 8.4 403 Forbidden

说明已经登录，但当前用户没有权限。

常见情况：

```text
普通用户访问用户管理、角色管理、操作日志
普通用户处理审批
非上传者删除别人的文件
```

### 8.5 400 Bad Request

常见原因：

```text
JSON 格式写错
GUID 参数写错
必填字段为空
Content-Type 不正确
上传文件字段名不是 file
```
