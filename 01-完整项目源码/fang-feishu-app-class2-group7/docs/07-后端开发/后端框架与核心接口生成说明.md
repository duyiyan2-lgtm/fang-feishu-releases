# 后端框架与核心接口生成说明

## 一、生成目标

本次生成内容对应项目方案中“组长 / 后端负责人”的工作范围，重点完成：

1. 后端基础框架。

## 七、启动方式

### 1. 启动依赖服务

在项目根目录执行：

```bash
docker compose -f deploy/docker/docker-compose.dev.yml up -d
```

会启动：

1. PostgreSQL，端口 `55432`，容器内部端口仍为 `5432`。
2. MinIO，端口 `9000` 和 `9001`。

当前后端文件上传默认使用本地 `storage/` 目录，MinIO 已作为后续扩展预留。

### 2. 启动后端

```bash
cd backend/src/FangFeishu.Api
dotnet run
```

默认访问：

```text
Swagger: http://localhost:5000/swagger
Health:  http://localhost:5000/health
```

实际端口以控制台输出为准。

## 八、四端如何接入

四端都请求同一个后端地址。

```text
Web 网站端       -> http://localhost:5000/api/v1
PC 客户端        -> http://localhost:5000/api/v1
手机端 Uni-app   -> http://localhost:5000/api/v1
微信小程序       -> http://localhost:5000/api/v1
```

登录后保存返回的 `token`，后续请求统一加请求头：

```text
Authorization: Bearer {token}
```

IM 实时通信地址：

```text
/hubs/im?access_token={token}
```

如果手机端或微信小程序实时通信不稳定，可以先用接口轮询：

```text
GET /api/v1/im/conversations/{id}/messages
```

## 十、后续开发建议

1. 前端负责人优先联调 `auth/login`、`auth/me`、`departments/tree`。
2. 业务前端优先联调通讯录、IM、文档、云盘。
3. 运维先启动 Docker Compose，确认 PostgreSQL 可连接。
4. 测试同学用 Swagger 或 Apifox 建立接口集合。
5. 如果要正式部署小程序，后端需要配置 HTTPS 域名并加入小程序合法请求域名。
